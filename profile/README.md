<p>这篇讲电脑接入海外住宅IP的具体做法。先区分系统代理、浏览器代理、客户端三种入口的覆盖范围，再给 Windows 与 macOS 的填写步骤，接着讲验证方式和五类常见故障，最后说多环境并行时的配置顺序。</p>
<h2>一、三种入口覆盖的范围不同</h2>
<p>系统代理是操作系统层面的设置，多数桌面软件会读取，但有些程序自己管网络，不读系统设置。</p>
<p>浏览器代理只影响浏览器，其他软件照旧走本地网络。客户端是在本机开一个本地端口，再把流量从端口转出去。</p>
<p>选择取决于要覆盖多少程序。只做网页操作用浏览器代理最省事，要用桌面客户端、同步工具和命令行，就得系统代理或客户端。</p>

<h2>二、Windows 的填写步骤</h2>
<p>在设置里进网络和 Internet，找到代理，把使用代理服务器打开。地址填服务商给的域名或 IP，端口照抄，别加空格。</p>
<p>保存后浏览器立即生效，部分程序需要重启。如果没变化，先看是不是还有别的代理软件在运行，抢了系统设置。</p>
<p>带账号密码的代理，系统设置里不弹认证框。要么把账号密码拼进地址栏，要么用本地转发工具代为认证。</p>
<h3>命令行要单独设</h3>
<p>命令行工具通常不读系统代理，需要设环境变量或加参数。这一步不做，会出现浏览器能用、脚本连不上的情况。</p>
<h2>三、macOS 与浏览器层</h2>
<p>macOS 在网络设置的高级里选对应服务，HTTP 与 HTTPS 两项填同一个地址和端口。只填一项，会有部分站点打不开。</p>
<p>浏览器层用扩展最省事，把地址端口写死，切换时点一下。装之前看清权限，部分扩展会读取浏览记录。</p>
<p>只想让特定站点走代理，用 PAC 脚本比全局更合适。规则写错的表现是某些站点一直转圈，调试时先简化到一条规则。</p>
<h2>四、客户端方式的取舍</h2>
<p>客户端能管全局、能分流、能看日志，代价是多一层软件，出问题时多一个变量。选之前先看三点。</p>
<p>是否支持按进程分流、是否能导出日志、是否在后台常驻多个进程。三点都满足，排障时才有抓手。</p>
<p>客户端会在本机开监听端口，其他程序把流量指过来。端口冲突是常见故障，换高位端口即可。</p>
<h2>五、验证与五类故障</h2>
<p>验证分三步：出口地址是否为目标地址、解析结果是否跟随出口地区、长连接是否稳定。只看第一步，容易漏掉解析泄露。</p>
<p>保存后无变化，多是另一个代理在抢设置。能开网页但登录失败，多是时区语言与出口地区不匹配。</p>
<p>部分站点打不开，多为分流规则过严或证书问题。速度忽快忽慢用长 ping 区分本地抖动与出口拥塞。</p>

<h2>六、多环境并行的配置顺序</h2>
<p>先确定每个环境用哪个出口，写下来贴在手边。再用不同本地端口区分，一个环境一个端口，一一对应。</p>
<p>浏览器多开用不同的用户配置目录，每个目录绑一个代理端口。Cookie 与登录态天然隔离，不用装两套浏览器。</p>
<p>全部配好逐个验证出口地址，确认没有串线。串线最难发现，表面一切正常，只有查出口地址才看得出来。</p>
<h2>常见问答</h2>
<h3>系统代理和客户端选哪个？</h3>
<p>答：看覆盖需求。只做网页操作用系统代理足够，要覆盖桌面程序与命令行就用客户端，两者不必同时开。</p>
<h3>填了地址端口还是连不上？</h3>
<p>答：先确认端口是否被占用，再确认代理是否要求认证。带认证的代理在系统设置里通常填不进去，需要转发工具。</p>
<h3>需要改 DNS 吗？</h3>
<p>答：建议改。只转发网页流量时解析仍走本地，会与出口地区不一致，用客户端接管全部流量可以避免这个问题。</p>
<h3>一台电脑能接几个住宅IP？</h3>
<p>答：取决于端口数量与客户端能力。常见做法是一个环境一个本地端口，同时跑三到五个比较稳妥。</p>
